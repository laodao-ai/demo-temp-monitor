# 注销设备为硬删除，读数由外键级联删除

**Status: Accepted** · 来源 change：`temp-monitor-baseline`（2026-10-15）

服务提供设备注册和注销。注销后，该设备的历史读数是否保留，需要定一个规则。

本项目是教学示例，没有查询或审计需求。设备 ID 由客户端在注册时给出，格式 `[a-z0-9-]{1,64}`。

## Decision

- 注销 = 从 `devices` 表删除该行（`DELETE /devices/{id}`）。
- `readings.device_id` 带外键 `REFERENCES devices(id) ON DELETE CASCADE`，该设备的读数由数据库级联删除（`db/migrations/0001_init.sql`）。
- 同一 ID 注销后可重新注册，视为新设备，没有历史。
- 向未注册或已注销的设备上报读数，返回 404（`httpapi` 把 `store.ErrNotFound` 映射为 404）。
- 注销不存在的设备同样返回 404。

## Considered Options

- **软删除（加状态列）**：否决。要处理 ID 的唯一约束和所有查询的状态过滤，教学示例用不到。
- **应用层先删读数再删设备**：否决。两步之间有并发窗口，外键级联由数据库保证。
- **硬删除加外键级联（采用）**。

## Consequences

- 系统镜：规则落在数据库约束上，应用代码无需手写级联。并发的「注销与上报」竞态由契约套件的 `ConcurrentDeleteAndReport` 覆盖。
- 用户镜：注销不可恢复，读数一并消失。重新注册同 ID 不会找回历史。
- 开发循环镜：无状态过滤，查询与测试更简单。将来要保留历史，需要改表结构并新写一篇 ADR 取代本篇。
- 主次：简单和一致性为主，历史可追溯为次。
