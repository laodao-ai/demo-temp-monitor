# 测试脚本退出码等于失败用例数（上限 125），零用例时退出 1

**Status: Accepted** · 来源 change：`temp-monitor-baseline`（2026-10-15）

`scripts/test.sh [unit|integration|all]` 用 `go test -json` 加 jq 统计结果。
脚本的退出码要让调用方一眼看出失败数，同时不能出现假绿。

shell 退出码只有 8 位，超过 255 会回绕。126 起被 shell 保留。
另外，build tag 写错或测试函数名拼错时，实际跑了 0 个用例，`go test` 仍然报成功。

## Decision

- 退出码 = 失败用例数 M。M 大于 125 时退出 125。
- 某一层已执行用例数（通过加失败）为 0 时，退出 1。汇总行照常输出，stderr 另打 `no tests executed in <层> layer`。这是「退出码跟随失败数」的唯一例外。
- `go test` 非零退出但 M 为 0（如进程被杀）时，按 1 个失败计。
- 计数口径（实测自 go1.27.1 的 `go test -json`）：
  - 只数带 `Test` 字段的 pass、fail、skip 事件。子测试与父测试各算一条。
  - 编译失败的包只有一条包级 fail，无用例事件。该包无用例级 fail 时计 1 个失败。
  - 无测试文件的包只有包级 skip，不计数。
- 唯一实现位置：`scripts/test.sh` 的 `count_filter` 与末尾的退出逻辑。

## Considered Options

- **有失败一律 exit 1**：否决。调用方看不到失败数，脚本也就少了一项信息。
- **退出码 = 失败数，不设上限**：否决。256 个失败会回绕成 0，报假绿。
- **零用例靠人看汇总行判断**：否决。人不看汇总时会放过 0 用例的绿，违反「已执行用例数大于 0」的完成标准。
- **失败数加零用例例外（采用）**。

## Consequences

- 系统镜：计数逻辑依赖 `go test -json` 的事件形态，Go 升级后需重测口径。
- 用户镜：「没跑到用例」显式变红。失败数 126 起不再可区分，被压成 125。
- 开发循环镜：脚本多一个分支，jq 过滤器要读懂才能改。口径已写在 design 的 Test Runner 一节。
- 主次：不假绿优先，脚本复杂度为次。
